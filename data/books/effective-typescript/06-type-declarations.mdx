라이브러리를 사용하는 코드가 타입 검사를 받으려면 라이브러리의 타입 정보도 필요하다. 실행되는 코드와 타입 선언이 어디서 제공되고, 어떤 버전으로 관리되는지 함께 확인해야 한다.

## typescript와 @types의 의존성 관리

일반적인 애플리케이션에서는 컴파일러와 타입 선언 패키지를 개발 의존성에 둔다. 컴파일과 타입 검사에 사용하고, 생성된 자바스크립트를 실행할 때는 필요하지 않기 때문이다.

| 구분               | 역할                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| `dependencies`     | 애플리케이션이나 패키지에서 사용하는 일반 의존성이다.                 |
| `devDependencies`  | 개발, 빌드, 테스트 등에 사용하는 의존성이다.                          |
| `peerDependencies` | 패키지가 함께 사용될 호스트 도구나 라이브러리의 호환 범위를 표현한다. |

`peerDependencies`는 단순히 ‘런타임에 필요하지만 직접 관리하지 않는 패키지’라고만 정의하기 어렵다. 플러그인이 어떤 버전의 호스트와 함께 동작하는지 알리는 용도로 이해하면 좋다. ([npm 공식 문서](https://docs.npmjs.com/cli/v11/configuring-npm/package-json#peerdependencies))

라이브러리가 타입 선언을 함께 제공하면 별도의 `@types` 패키지가 필요하지 않다. 타입이 없는 라이브러리는 해당하는 `@types` 패키지가 있는지 확인한다. ([TypeScript 공식 문서](https://www.typescriptlang.org/docs/handbook/declaration-files/consumption.html))

또한 라이브러리를 배포할 때는 자신의 선언 파일이 외부 타입을 참조하는지 확인해야 한다. 사용자에게도 필요한 타입 의존성까지 무조건 개발 의존성으로 옮겨서는 안 된다. ([타입 선언 배포 문서](https://www.typescriptlang.org/docs/handbook/declaration-files/publishing.html#dependencies))

## 세 가지 버전 함께 확인하기

라이브러리와 타입 선언이 별도 패키지라면 세 가지 버전의 관계를 살펴본다.

1. 실제 실행되는 라이브러리의 버전
2. 라이브러리의 타입을 설명하는 선언 패키지의 버전
3. 선언 파일을 읽고 검사하는 타입스크립트 컴파일러의 버전

라이브러리만 업데이트하면 타입 선언에 새 API가 없을 수 있다. 반대로 선언이 더 새로운 API를 설명하면 타입 검사는 통과했는데 실행 중에 함수가 없다는 오류가 발생할 수 있다.

선언 파일이 사용하는 문법을 현재 컴파일러가 지원하는지도 확인해야 한다. 의존성 트리에 같은 `@types` 패키지의 여러 버전이 있는 경우에는 서로 다른 타입 선언이 충돌하는지도 살펴본다.

## API 주석에는 TSDoc 사용하기

문서 주석은 함수의 역할과 매개변수, 반환값을 설명한다. 편집기에서 함수를 사용할 때 이 내용을 확인할 수 있다.

```typescript
/**
 * 주문 번호를 화면에 표시할 문자열로 만듭니다.
 *
 * @param orderId - 표시할 주문 번호
 * @returns 주문 접두사를 붙인 문자열
 */
function formatOrderLabel(orderId: number): string {
  return `주문 #${orderId}`
}
```

타입스크립트 코드에서는 매개변수의 타입을 주석에 다시 적기보다, 타입만으로 알 수 없는 의미와 사용 조건을 설명한다.

TSDoc은 타입스크립트의 문서 주석 문법을 표준화하려는 규약이다. JSDoc과 비슷한 형태를 사용하지만 두 이름이 같은 규약을 뜻하는 것은 아니다. 사용하는 문서화 도구의 지원 범위도 확인한다. ([TSDoc 문서](https://tsdoc.org/))
