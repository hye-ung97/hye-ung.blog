트랜잭션은 여러 읽기와 쓰기를 하나로 묶어, 전부 성공하거나 전부 실패하게 만든다. 애플리케이션은 그 덕분에 부분 실패와 동시성 문제의 상당 부분을 데이터베이스에 맡긴다. 7장은 그 '상당 부분'이 정확히 어디까지인지를 다룬다.

## ACID가 실제로 뜻하는 것

원자성은 동시성보다 중단 가능성에 가깝다. 중간에 실패하면 지금까지 쓴 것을 버리고 처음부터 다시 시도할 수 있다는 뜻이다. 일관성은 데이터베이스가 아니라 애플리케이션이 지키는 불변식이고, 격리성은 동시에 실행된 트랜잭션이 서로를 못 본 것처럼 동작한다는 약속이다.

## 완화된 격리 수준

직렬성 격리는 비싸서 대부분의 데이터베이스는 더 약한 수준을 기본값으로 쓴다. 커밋 후 읽기는 더티 읽기와 더티 쓰기를 막고, 스냅숏 격리는 트랜잭션이 시작한 시점의 일관된 스냅숏을 읽게 해 준다.

스냅숏 격리도 갱신 손실은 막지 못할 수 있다. 두 트랜잭션이 같은 값을 읽고 각자 고쳐 쓰면 한쪽의 변경이 사라진다. 원자적 연산을 쓰거나, 읽을 때 명시적으로 잠근다.

```sql
BEGIN;
SELECT balance FROM accounts WHERE id = 1 FOR UPDATE;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
COMMIT;
```

## 쓰기 스큐와 팬텀

더 교묘한 문제는 쓰기 스큐다. 두 트랜잭션이 같은 조건을 확인하고 서로 다른 레코드를 고치면, 각자는 규칙을 지켰는데 합쳐 보면 규칙이 깨진다. 조건을 확인한 결과를 다른 트랜잭션의 쓰기가 바꾸는 이 현상을 팬텀이라고 부른다. MySQL에서 이 현상을 직접 확인한 과정은 [REPEATABLE READ인데 왜 Phantom Read가 안 생길까?](/blog/mysql-repeatable-read-phantom-read)에 정리했다.

## 직렬성을 얻는 세 가지 방법

첫째는 정말로 한 번에 하나씩 실행하는 것이다. 트랜잭션이 짧고 데이터가 메모리에 들어갈 때 의외로 잘 동작한다. 둘째는 2단계 잠금으로, 읽기도 잠그기 때문에 처리량과 응답 시간을 크게 희생한다.

셋째는 직렬성 스냅숏 격리(SSI)다. 일단 잠그지 않고 실행한 뒤, 커밋할 때 자신이 읽은 데이터가 그사이 바뀌었는지 확인해 충돌하면 중단한다. 경합이 적은 작업 부하에서는 2단계 잠금보다 훨씬 낫다.
